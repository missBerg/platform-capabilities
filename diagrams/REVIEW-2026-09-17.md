## 1. The constraint that drives everything: PDF page width

A figure is scaled to the text column. US Letter with 1 in margins gives a
6.5 in (468 pt) column, so effective text size is `468 / canvas_width * font_px`.

Every diagram is below the 8 pt floor for print. Sublabels (11 px) are worse.

**Budget for the final set**

- Canvas width <= 720 units. Height <= 600 units (about half a page).
- Fonts: primary label 14 px (9.1 pt), sublabel and edge label 12 px (7.8 pt),
  section header 14 px bold. Nothing below 12 px.
- Edge stroke 2 px, shape stroke 1.5 px. No sketch jitter (it turns to mud
  when downscaled).
- Render at `--scale 3` for embedding.
- Add a `--pdf-check` to `scripts/render.py` that prints the effective pt
  size at 6.5 in and warns below 7 pt.

## 2. Style rules for the whole set

- **Clean flavour** for every paper figure. Conversion is a token strip on the
  hand-polished `.drawio` (validated on factor 4): remove `sketch=1;`,
  `curveFitting=1;`, `jiggle=2;`, `fillStyle=solid;`; set
  `fontFamily=Helvetica`; keep `curved=1`. Ship this as
  `scripts/restyle-diagram.py` (idempotent) rather than regenerating from
  specs, which would destroy layout work.
- **Colour roles**: light blue = capability-side things; dark blue = the one
  platform anchor per diagram; gold = people and ownership only; grey =
  implementation internals; red = cost of failing. Consequences: factor
  tags and trigger tags move from gold to blue; capability principles become
  light-blue boxes, platform principles stay dark-blue tags.
- **Contrast fixes**: gold tag fill `#B5915A` fails WCAG AA with white text
  (2.96:1). Darken to `#8A6A38` (5.0:1) in both component libraries. Sublabel
  grey is now `#4B5563` in the generator; the restyle script swaps `#6B7280`
  in existing files.
- **One red callout per factor diagram**, bottom-right, headline plus
  "fails the factor". No other prose notes. No titles in the image.
- **Icons**: at most one badge per primary box. Drop the `consumer-api` port
  blob (factor 1); fix the stamp in the library separately.

## 5. Follow-up (2026-09-20): reviewer comments on the embedded figures

Reviewer comments on the Google Doc (Stefan, Bryan, Sriharsha, Simon, Corbin)
all pointed the same way: text in the figures is too small next to the body
text, and several labels duplicate or contradict the prose. Applied:

- **Portrait, not landscape.** Every figure now uses a `TB` layout or a
  two-lane `LR` layout so it fits the column by height; canvas widths went
  from 488–714 units to 320–543 (12 px text reads at 10.3–13.1 pt, up from
  7.9–11.5). `factors-overview` is a 320-wide numbered stack.
- **Less text.** Prose the document already carries was removed: the
  factor-overview glosses, the "Internal" steps list in factor 2 (Bryan's
  recovery-procedures thread; Simon asked for "never the consumer's
  problem" to go), the property tags and dependency list are now one-line
  sublabels, the "proven by the five factors" tag, consumer teams and the
  four results in the bottleneck figure.
- **Match the document's words.** "Platform ecosystem model" (not
  architecture), "Centralized platform group", "Core platform", producers
  "contribute & maintain" / consumers "request & use", actors in the paper's
  order (consumers, platform ops & leadership, producers, finance,
  security & compliance), "Observable" everywhere.
- **New `centralized-friction-loop`** replaces the old "techno-social doom
  loop" figure in the slot after the four bullet results: six nodes, no
  "doom", no "snowflake instances" (Sriharsha), no toll tags. The bottleneck
  figure now shows the two ownership outcomes the paragraph above it names.
- Generator: `labelOffsetX` added (labels on vertical edges), documented in
  the skill with the other layout knobs.
